# throughline

顧客に向き合う技術者が、案件と日々の仕事の流れを一本の線として持ち続けるためのスキルです。
「残っている仕事は何か」「このワークフローを作ったがどうか」「会議の準備」「議事録を整理して」「この案件いまどこまで」のような日常の相談に、必要な観点と次の行動を示します。複数の担当業務から、今日優先することとその理由を選ぶ相談にも使えます。

| 枠 | 内容 |
|---|---|
| 位置 | 案件の目的と全体の流れの中で、いまどこにいるか |
| 観点 | この相談に当てるとよい観点を2〜3個(ビジネス、目的と枠、業務の理解、進行) |
| ビジネス | お金の流れ、顧客のアウトカム、原価、次の案件への効き方。分かっている値と分かっていない値 |
| 次の一手 | いま取れる行動を1つか2つ |

案件を継続して扱うときは台帳(`case.md`)を持ち、会議やチャットの記録を観点表へ畳み、開いている約束と分岐した作業を追います。独立した相談や文書の点検は、台帳や出力ファイルなしで進めます。

## モード

| モード | 使う場面 |
|---|---|
| `ask` | 日常の相談、複数の担当業務から今日の行動を選ぶ相談 |
| `prepare` | 会議の前に、聞くことと目的・制約・期限を用意する |
| `digest` | 議事録やチャットの記録を観点表と約束に畳む |
| `next` | 結果を受けて、分岐する作業と相手へ返すものを出す |
| `status` | 案件の現在地を一枚にする |
| `check` | 計画・判断・文書を原則と観点で点検する |
| `weekly` | 一週間の変化と次週の焦点をまとめる |

## インストールと使い方

```bash
npx skills add rillflow/skills --skill throughline
```

手動で配置する場合は、`references/` を含む `skills/throughline/` 全体を、使用するエージェントのスキルフォルダにコピーするかリンクします。

最初に `references/policy.md` を自分の環境に合わせて書き、`~/.agents/throughline/policy.md` に置きます。顧客から受け取った情報を読んでよい実行環境と、その判定の手がかり、台帳と週次ログ行の置き場所をここで決めます。設定が無いときは、顧客受領情報を読まない側に倒れます。

作業フォルダだけを見せるサンドボックスや、ホームディレクトリが作業のたびに作り直される環境では、作業フォルダの `.throughline/policy.md` に置きます。こちらが先に読まれます。読み取り専用で見せられるなら、そうしてください。エージェントが自分の許可を書き換えられなくなります。

台帳が案件の状態を持つので、セッションを新しく始めても、同じ作業フォルダで複数のセッションを並べても、台帳から続けられます。

- 「この案件、残っている仕事は何ですか。」
- 「この担当業務の要約から、今日優先することと完了条件を示してください。」
- 「このワークフローを作りました。観点で見てください。」
- 「明日の顧客会議の準備をしてください。」
- 「この議事録を整理して、次にやることを出してください。」
- 「今週何が変わりましたか。」

今日の行動は、確認できた目標・期待する結果と、本人の責任・約束・期限・詰まりをつなげて選びます。目標や過去の値がなくても、現在の根拠から条件付きで進めます。組織の目標や評価制度は、利用者が示す実行時の資料として扱います。複数の仕事を見るために顧客の原文や他案件の台帳を自動で集めず、許可された要約だけを使います。

## 構成

- `SKILL.md`: エージェントが読む手順
- `references/lenses.md`: 観点表(A ビジネス / B 目的と枠 / C 業務の理解 / D 進行)
- `references/principles.md`: どの場面でも当てられる原則集
- `references/ledger.md`: 案件台帳の形
- `references/output.md`: モードごとの出力形式
- `references/policy.md`: 利用者の設定の雛形
