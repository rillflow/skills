# 原則集 — どの場面でも当てられる短い言葉

`ask` と `check` で、相談に効くものを1〜3個だけ引く。当てたら、この相談ではどういう意味になるかを1文添える。
一覧を全部並べない。

## 問う

- 手段を磨く前に、目的を疑え。
- 問題は、一文にした瞬間から解けはじめる。
- 問いを一段上げれば、答えが変わる。
- 手段は捨てられる。残すのは結果だ。
- 症状を叩くより、原因を消せ。

## 見る

- 答えは、相手の席に座ると見える。
- 十倍と十分の一で考えると、思い込みが剥がれる。
- よその分野が、もう答えを持っている。

## 解く

- 一番良い仕組みは、要らなかった仕組みだ。
- 妥協の前に、矛盾を探せ。
- 両立できないのは、同じ時と場所で求めるからだ。
- 足りないものは、たいてい手元にある。
- 大きすぎる問題は、分ければ解ける。
- 困りごとは、そのまま資源になる。
- 壊し方を考えると、守り方が見える。
- 解決策は、次の問題を連れてくる。
- 一つ直す前に、次に起きる問題まで読め。
- 同じ指摘が戻るなら、直す場所ではなく、問いの立て方を疑え。

## 確かめる

- 「良くなった」は、測ってから言う。
- 失敗が見えないものは、自動化できない。
- 引用できることだけ、断言する。
- 判断を変えないものは、削っていい。
- 自分の頭の中だけで完結させない。

## 仕事にする

- 目的と制約と期限が、仕事を仕事にする。
- 新しい道具で、古い仕事をなぞらない。
- 関わった瞬間から、それは自分の物語だ。
- 自分が要らなくなる形まで作って、完成だ。
- 「ありがとう」と、対価は別だ。
- 次の仕事は、信頼が連れてくる。

## 由来

「解く」の多くは TRIZ(発明的問題解決の理論)の考え方(理想の最終結果、矛盾の解消、分離、資源、寸法・時間・費用の操作、機能を基準にした検索、二次的な問題)を一文にしたもの。
それ以外は、顧客に向き合う技術者の運用指針と、筆者の仕事の習慣から。特定の組織や人の名前は含まない。
