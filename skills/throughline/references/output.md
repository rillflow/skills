# 各モードの出力形式

すべての出力は1行目にゲートの判定を書く。

```
ゲート: 社内情報のみ / 顧客受領情報を含む(実行環境: <名前>, 許可: あり)
```

## ask(日常の相談)

```
位置: <案件コード> <段階> — ここまで <一文> / この先 <一文>
(残っている仕事の相談なら、ここに未完了の約束と作業の表)
観点: <欄名または原則> — この相談では <一文>
      <欄名または原則> — <一文>
ビジネス: お金の流れ <値 or 未確認> / 顧客のアウトカム <値 or 未計測> / 原価 <値 or 未計測> / 次の案件 <値 or 未確認>
次の一手: 1. … 2. …
```

相談が「残っている仕事は何か」なら、位置の直後に台帳の「開いている約束」と「分岐した作業」の未完了を表で並べ、そのあとに観点・ビジネス・次の一手を続ける。
相談が「作ったものの評価」なら、観点は B(単純な置き換えの兆候)と C(入口と出口、使う人)から選ぶことが多い。

## prepare

```
# 会議準備 <案件コード> <会議名> <日付>

## TCD の下書き
- Target / Constraints / Deadline(台帳から。無ければ「未設定 — 冒頭で確認」)

## 聞くこと(優先順)
1. <質問> — 観点: <欄名>(空欄 / 前回更新 YYYY-MM-DD)
   (5〜8個。A のビジネスと空欄を先に)

## アジェンダ案

## 前回からの持ち越し
- 開いている約束
```

## digest

```
# 記録の整理 <案件コード> <記録名> <日付>

## 観点表の更新(変わった欄だけ)
| 欄 | 前の値 | 新しい値 | 根拠 |

## 決定 / 未決とその理由 / 約束(誰が・誰に・何を・いつまで)

## 製品の不具合・要望(チケット下書き)
- 再現 / 期待 / 実際

## 次の作業(next へ渡す)

## 次の会議で聞くこと

## 週次ログ行
<日付> | <案件コード> | <何が変わったか(顧客名・業務内容なし)> | <次の一歩>
```

週次ログ行は policy.md に記した場所へ追記する。案件コードは社内で通じる略号にする。

## next

```
# 次の作業 <案件コード> <日付>

## 分岐する作業
| 作業 | 種類 | 担当 | 期限 | 出どころ | 状態 |

## 相手へ返すもの
- 誰に / 何を / いつまでに / 下書き

## 台帳の更新
- 接点の履歴 / 開いている約束 / 分岐した作業
```

種類がチケットのものは、下書き本文を末尾に付ける。起票は利用者の指示があるときだけ。

## status

```
# 案件の現在地 <案件コード> <日付>

一言: <目的 → 段階 → 次の会議までにやること>

## 接点の時系列(直近5件)
## 開いている約束
## 観点表で空いている欄
## ビジネス A の現在値
```

## check

```
# 観点チェック <対象> <日付>

## 当たる原則(1〜3個)
- <原則> — この対象では <一文>

## 観点表で見ると
| 欄 | 対象での状態 | 見落とし・確認すること |

## 直すなら
1. …
```

## weekly

```
# 週次 <期間>

## 案件ごとの変化
| 案件コード | 段階 | 何が変わったか | 開いている約束 | 次週の焦点 |

## 観点表 A の変化
| 案件コード | 欄 | 前 | 後 |

## 空いたままの欄(3週以上)

## 次週の焦点(全体で3つまで)
```

`weekly` は台帳と週次ログ行だけを材料にする。記録の原文を読み直さない。
