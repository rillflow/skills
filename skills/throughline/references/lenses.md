# 観点表 — 記録から読み取り、次に聞き、相談に当てる

A〜D の順に見る。各欄は「読み取ったこと」「根拠(発言の引用と時刻、または文書の位置)」「更新日」を持つ。
根拠の無い欄は空のまま残す。空欄は `prepare` の質問になり、`ask` では「まだ分かっていないこと」として示す。

## A. ビジネス

| 欄 | 読み取ること | 空欄のときの聞き方の例 |
|---|---|---|
| お金の流れ | 誰が、何の対価として払うか。新規・更新・拡大のどこに効くか。契約の形と次の更新時期 | 「この取り組みは、どの予算・どの契約から出ていますか」「次の見直しはいつですか」 |
| 顧客のアウトカム | 変わる業務と指標(工数、リードタイム、件数、誤り)。導入前の値があるか。顧客が自分の言葉で言った成功条件 | 「うまくいったと判断する基準は何ですか」「いまは1件あたりどのくらいかかっていますか」 |
| 原価 | モデル利用料、実行時間、人の工数、インフラ。1件あたりの原価の見積もりと根拠 | (社内で確かめる欄。顧客会議では聞かない) |
| 価値と価格の差 | 顧客が感じている価値と、請求の差。高い・安いという発言 | 「この結果に対して、いまの費用感はどう見えていますか」 |
| 次の案件・拡大 | 横展開の発言、隣の部署や業務、予算や中期計画の言葉、意思決定者 | 「これができるなら、他にどんな業務がありますか」(例を2つ添える) |
| 型になるか | この案件の形が、担当者なしでも他の人が売り、届けられるものになるか | (社内で判断する欄) |

## B. 目的と枠

| 欄 | 読み取ること | 空欄のときの聞き方の例 |
|---|---|---|
| TCD | Target(何ができたら勝ちか)、Constraints(前提と制約)、Deadline(いつまで)が確認できたか | 「今回決めたいことは何ですか」「いつまでに必要ですか」 |
| 目的の種類 | 利用者や記録が示す目的をそのまま残す。例: 関係構築、業務の改善、明白な投資対効果、事例化、業界向けの見本、複数の仕組みの下地。例に当てはまらない目的も扱う | 「今回の取り組みで、一番得たいものは何ですか」 |
| 単純な置き換えの兆候 | 「いまの業務をそのまま道具に」という要望。あれば警告として残す | 「この業務の前後で、変わってよい手順はありますか」 |

## C. 業務の理解

| 欄 | 読み取ること | 空欄のときの聞き方の例 |
|---|---|---|
| 体感の3段 | 楽になった感覚があったか。無ければどこで引っかかったか。さらに楽にするには | 「使ってみて、楽になった感覚はありましたか」 |
| 入口と出口 | 対象作業の前工程(受領、取り込み、準備)と後工程(確認、承認、基幹システム、成果物の行方) | 「この作業の前は何をしていますか。終わった後はどこへ渡しますか」 |
| 物理環境 | 画面、机、紙、原本の返却など、画面の外の制約 | 「どんな画面と机で作業していますか」 |
| 目印と閾値 | 熟練者が使う目印。簡略な手順へ切り替える判断基準(金額、件数など) | 「どこを見て区切りを判断していますか」「簡略でよいと決める基準はありますか」 |
| 稀な事例 | 精度の壁になる例外。出しすぎと出さなすぎのどちらを嫌うか | 「困った例を1つ教えてください」「多めに出るのと、漏れるのは、どちらが困りますか」 |
| 使う人 | 熟練者か次の世代か。信頼の仕方(原本と照合する、根拠へ飛ぶ) | 「誰がこの結果を使いますか。その人はどう確かめますか」 |
| 転記先 | 出力が流れていく既存の帳票やシステム | 「この結果は、最後にどこへ書き写しますか」 |
| 文書の扱い | 保管義務、廃棄、返却 | 「書類はいつまで保管しますか」 |

## D. 進行

| 欄 | 読み取ること |
|---|---|
| 決定 | 決まったこと。誰が決めたか |
| 未決とその理由 | 決まらなかったことと、何が足りないか |
| 約束 | 誰が、誰に、何を、いつまでに。自社側と相手側の両方 |
| 製品の不具合・要望 | 再現手順、期待した動作、実際の動作。チケットの下書きになる |
| リスク | 前提が揺らいだ箇所。担当者の交代、予算、日程、法務 |

## 由来

A は「お金の流れ → 顧客のアウトカム → 社内のアウトカム → 時間」の順で仕事を見る習慣から。
B は仕事の依頼に目的・制約・期限を求める運用と、既存業務の単純な置き換えを避ける方針から。
C は顧客ヒアリングの記録に繰り返し現れた聞き方を一般化した。特定の顧客や業務の内容は含まない。
D は会議記録の一般的な項目。
