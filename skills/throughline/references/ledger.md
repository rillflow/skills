# 案件台帳 `case.md` の形

案件の継続記録が必要なときに使う。1案件1ファイル。独立した`ask`と`check`は台帳なしで進める。新しく確定した決定・約束・作業があり、記録する権限があるときだけ、該当案件を更新する(SKILL.md§3・§8)。記録の原文は置かず、リンクかファイル名だけを書く。

```markdown
# <案件コード> — <一言>

- 案件コードの確認: <利用者の確認と出どころ / 未定>

## 目的と TCD
- 目的の種類: <利用者や記録が示す目的。lensesのBの例に限定しない>
- Target: <何ができたら勝ちか>
- Constraints: <前提・制約>
- Deadline: <いつまで>
- 更新: YYYY-MM-DD(根拠: <会議名または文書>)

## 全体の流れ
- 段階: <例: 導入前ヒアリング / 試行 / 本番準備 / 運用 / 横展開>
- ここまで: <一文>
- この先: <一文>
```

規則:

- 案件コードは、顧客名やその略称に由来しないものを利用者に確認する。顧客名、顧客の略称、顧客名を含むフォルダ名から作成しない。確認するまでは「未定」とし、週次ログ行の扱いは[output.md](output.md)に従う。既存のコードにも同じ規則を適用する
- 約束は、担当・相手・対象の作業・期限・出どころを対応づけて記録する。作業は、担当・対象の作業・期限・出どころを対応づける。出どころには文書の位置や発言時刻を記し、その期限がどの作業に掛かるかを確認する。期限の根拠がない作業は「未定」とし、別の約束・会議の日付・TCDのDeadlineを転用しない。担当や約束の相手も根拠がなければ「未定」とする
- 既存の台帳に「出どころ」列がなければ、更新する行の作業や約束に根拠を添える。列を追加するためだけに、台帳全体を置き換えない
- 「状態の根拠」は、作業内容や担当の出どころと分け、状態を直接示す短い引用と記録の位置を記す。新しい作業に状態の記載がなければ、状態は「未確認」、状態の根拠は「記載なし」とする
- 未来の約束、担当の割り当て、先行条件だけから「未着手」「進行中」「待ち」「完了」を推定しない。先行条件は作業の説明か注記に残し、現在の状態にしない。提案は提案のまま扱い、状態を付けて確定した合意にしない
- 既存の状態に根拠があり、新しい記録が状態を述べていなければ、その状態と根拠を残す。新たに現在の状態を確認したものとして更新しない。「状態の根拠」列が無い台帳は、変更する状態のセルか該当行に根拠を添え、列の追加だけを理由に全体を書き換えない
- 「接点の履歴」には、社内で顧客の代わりに要望を持ってくる同僚との会話も同じ行の形で書く。相手の列で区別する
- 「開いている約束」は状態が「完了」になったら履歴へ移し、この表からは消す
- 観点表の「更新」列は、その値を最後に確かめた日。`prepare` はここを見て古い欄を質問に変える
- 「全体の流れ」は案件の`ask`で台帳を使う場合の「位置」の出どころ。段階が変わったら必ず書き換える
- 台帳の置き場所は SKILL.md §3 と policy.md に従う。顧客受領情報を含む案件の台帳を、許可されていない環境へ持ち出さない

状態の判定例:

| 記録の記載 | 状態 | 状態の根拠 |
|---|---|---|
| 「担当者が次回までに確認する」 | 未確認 | 記載なし |
| 「確認作業はまだ始めていない」 | 未着手 | 「まだ始めていない」＋記録の位置 |
| 「確認作業は完了した」 | 完了 | 「完了した」＋記録の位置 |
