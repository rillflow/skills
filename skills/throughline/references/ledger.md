# 案件台帳 `case.md` の形

1案件1ファイル。全モードがこれを読み、更新する。記録の原文は置かず、リンクかファイル名だけを書く。

```markdown
# <案件コード> — <一言>

## 目的と TCD
- 目的の種類: <lenses B「目的の種類」の値>
- Target: <何ができたら勝ちか>
- Constraints: <前提・制約>
- Deadline: <いつまで>
- 更新: YYYY-MM-DD(根拠: <会議名または文書>)

## 全体の流れ
- 段階: <例: 導入前ヒアリング / 試行 / 本番準備 / 運用 / 横展開>
- ここまで: <一文>
- この先: <一文>

## 接点の履歴(新しい順)
| 日付 | 相手(顧客 / 社内の代理 / 社内) | 種類(会議・チャット・メール) | 決定 | 約束 | 記録 |
|---|---|---|---|---|---|

## 開いている約束
| 誰が | 誰に | 何を | いつまで | 状態 |
|---|---|---|---|---|

## 観点表の最新値
### A. ビジネス
| 欄 | 値 | 根拠 | 更新 |
|---|---|---|---|
| お金の流れ | | | |

## 次の会議で聞くこと
- <空欄・古い欄から作った質問>

| 作業 | 種類(チケット・開発・ワークフロー・文書) | 担当 | 期限 | 状態 | リンク |
|---|---|---|---|---|---|
```

規則:

- 「接点の履歴」には、社内で顧客の代わりに要望を持ってくる同僚との会話も同じ行の形で書く。相手の列で区別する
- 「開いている約束」は状態が「完了」になったら履歴へ移し、この表からは消す
- 観点表の「更新」列は、その値を最後に確かめた日。`prepare` はここを見て古い欄を質問に変える
- 「全体の流れ」は `ask` の「位置」の出どころ。段階が変わったら必ず書き換える
- 台帳の置き場所は SKILL.md §3 と policy.md に従う。顧客受領情報を含む案件の台帳を、許可されていない環境へ持ち出さない
