# 設計の根拠と効果の限界

検討基準日は2026-09-17です。このスキルはTRIZ原典を翻訳・転載する教材ではなく、公開原典から得た思考の動きと実証研究の限界を反映した個人の作業指針です。原典の手順説明と、このスキルの効果は別です。

## 原典と適用範囲

- [AltshullerのARIZ-85V](https://altshuller.ru/triz/ariz85v.asp): 導入、1〜9部、表1、表2を検討しました。単純な原理選択を超え、問題モデル、資源、技術化、検証を扱います。
- [76標準の全文](https://www.altshuller.ru/triz/standards.asp)、[40原理](https://www.altshuller.ru/world/eng/technique1.asp): 特定の技術問題モデルで探索を助けます。標準番号と行列は、一般業務の自動回答機ではありません。
- [システム思考](https://altshuller.ru/triz/triz70.asp)、[RVS](https://altshuller.ru/triz/triz20.asp)、[ファンタグラム](https://www.altshuller.ru/triz/triz9.asp): 問題水準、制約、想像力を変換します。想像力の訓練結果を実際の解法として採用するには、現実の条件へ戻る必要があります。
- [MATRIZの道具体系](https://wiki.matriz.org/docs/triz/problem-solving-tools-5890/)と、各道具カードから参照される、機能・因果・トリミングの文書: 後代の分析方法です。古典の単一版と混同しません。
- [KhomenkoによるOTSMの解説](https://otsm-triz.org/sites/default/files/ready/khomenko050120supershortintroductionintoclassicaltrizandotsm.pdf): つながった非標準問題を扱う後代の一般化です。専門知識と定量評価を代替しません。

原典の公式、例、訓練課題全体は含めません。原典へのリンクが公開されているだけで、再配布ライセンスがあるとは考えません。TRIZ、RTV、OTSMの教材全体を実装したスキルでもありません。

## 実証根拠が変える動作

| 根拠 | 確認した範囲 | このスキルでの判断 |
|---|---|---|
| [Hernandez et al., 2013](https://doi.org/10.1115/1.4024976)、[Okudan et al., 2006](https://doi.org/10.1115/DETC2006-99483) | 一部の工学学生課題での新規性、多様性、概念数の改善。標本、課題、統制群の設定には限界がある | 発想支援として試すが、一般業務での効果に広げない |
| [Birdi et al., 2012](https://doi.org/10.1111/j.1467-9310.2012.00686.x)、[Haines-Gadd, 2015](https://doi.org/10.1016/j.proeng.2015.12.387) | アイデアの提案と現場での実装・成果は同じ結果ではない。Birdiは要旨の範囲を確認 | アイデアの魅力と実装後の効果を分ける |
| [AutoTRIZ](https://arxiv.org/abs/2403.13002)、[TRIZ-GPT](https://arxiv.org/abs/2408.05897) | 教材上の矛盾復元、TRIZの手順に沿ったプロンプト、解法の類似性が中心 | 手順の再現を創造性・実用性の証明と扱わない |
| [TRIZ Agents](https://arxiv.org/abs/2506.18783)、[TRIZBENCH](https://aclanthology.org/2026.findings-acl.1798/) | 前者は単一の工学事例での複数役割デモ。後者は矛盾、原理、根拠の下位課題評価 | 役割数を基本的に増やさず、原理検索と最終解法の品質を分ける |
| [Doshi・Hauser, 2024](https://doi.org/10.1126/sciadv.adn5290)、[Anderson et al., 2024](https://arxiv.org/abs/2402.01536) | 一部の課題で、個人の成果向上と集団の同質化が同時に観測された | 候補数と、実際の動作の仕組みの多様さを分ける |
| [Si et al., ICLR 2025](https://arxiv.org/abs/2409.04109) | NLP研究アイデアの匿名専門家評価、大量生成の重複と自己順位付けの限界 | 有名な最初の答えや、表現だけが変わった候補にとどまらず、採用評価を自己採点だけで終えない |
| [Wadinambiarachchi et al., CHI 2024](https://arxiv.org/abs/2403.11164) | 視覚設計で、生成画像による固定化を観測。テキストへの一般化は未検証 | 最初の例を正解として固定せず、別の構造・前提を比べる |
| [Hubert et al., 2024](https://doi.org/10.1038/s41598-024-53303-w)、[Kumar et al., 2025](https://aclanthology.org/2025.emnlp-main.1704/) | 発散指標と実際の有用性の違い、アイデアの背景にある根拠と、アイデア評価の限界 | 新規性、事実性、実現可能性、実際の効果を分ける |
| [Wang et al., 2024](https://aclanthology.org/2024.emnlp-main.1112/)、[Tran・Kiela, 2026 preprint](https://arxiv.org/abs/2604.02460) | 正解型推論で総予算を合わせた戦略比較。創造性の直接証拠ではない | 追加の推論・役割の効果を比べるとき、総コストと呼び出し回数を含める |

迅速な共有で先に答える規則は、利用者の要望と既存の共有・返信手順に由来します。上記の物語・発散実験がその伝達順を立証したわけではありません。固定した候補数、再発散の回数、特定モードの性能優位を、文献が検証したとは主張しません。

## 検証するとき

同じモデル、課題、根拠、道具、生成設定で、直接の依頼、構造化した発想、このスキルを比べます。迅速モードでは依頼に対して何を返すかという約束を守れたかと応答負荷を、深考モードでは異なる仕組み、制約充足、検証可能な案を評価します。スキル自体を直す評価では、作成とは独立に判定し、可能な場合は実際に実行して確かめます。

迅速モードでは独立した検討者を必須にしません。深考モードの独立判定は手順の一部ですが、それだけでスキルの品質優位を示したことにはなりません。検討者を使えない場合は未実施と記録します。パイロットの成果物、LLM判定、人が測った効果、実際の実装結果は別に報告します。
