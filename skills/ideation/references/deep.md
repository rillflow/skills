# 고찰 모드

충분한 시간을 써서 현재 문제 표현 밖의 대안까지 탐색한다. 사용자에게 필요한 결과와 허용한 범위를 유지한다. 요청에 시간·비용 제한이 있으면 그 안에서 탐색 깊이를 정한다.

## 문제 표현부터 비교한다

주어진 문제, 필요한 기능, 성공을 판단할 관측, 바꿀 수 없는 조건을 구별한다. 사용자가 고정한 선택과 단지 현재 쓰고 있는 수단을 섞지 않는다. 사실이 부족하면 문제를 닫아 버리지 말고 가정에 따른 후보로 분리한다.

현재 문제와 다른 표현을 비교한다. 예를 들어 처리 속도를 높일지, 처리할 필요를 없앨지, 다른 시점에 처리할지에 따라 탐색할 해법이 다르다. 이름만 추상화하지 말고 바뀐 문제 표현이 어떤 해법을 허용하는지 확인한다.

## 막힌 이유에 맞는 도구를 고른다

[TRIZ 사고 도구](triz.md)에서 필요한 부분을 읽는다. 같은 가족의 변형을 늘리기 전에 다른 작동 방식과 해결 수준을 탐색한다.

| 지금 확인한 상황 | 우선 검토할 도구 |
|---|---|
| 개선하면 다른 요구를 깨뜨림 | 모순의 근거 확인, 조건·시간·공간·전체와 부분의 분리 |
| 개선할수록 구성·설명·공수가 늘어남 | 필요한 기능과 이상적 결과, 자원 활용, 기능 이전·제거 |
| 같은 지점의 처치가 반복됨 | 시스템·하위·상위 수준과 앞뒤 시간, 원인과 책임 경계 |
| 해법이 비슷한 변형으로만 나옴 | 구조적 유추, 규모·시간·비용의 가정 변화, 다른 물리·정보 작용 |
| 아직 해결할 상충이 정해지지 않은 발상 | 사용자 결과·기능·시스템 경계를 바꾸어 기회 탐색 |

물리·기술 시스템의 어려운 발명 문제라면 [고전 TRIZ 심화](triz-classical.md)를 읽고 적합한 표준해·과학 효과·ARIZ 경로까지 확장한다. 전체 ARIZ를 선택했다면 첫 아이디어에서 멈추지 않고 기술화·도입 문제·반복 동작·전용 가능성까지 검토한다.

## 후보를 실제 조건으로 되돌린다

유망한 후보에는 무엇이 어떻게 작동해서 문제를 풀 수 있는지 적는다. 다른 분야의 사례를 가져왔다면 대응하는 기능·상충과 대응하지 않는 조건을 구별한다. 익숙한 해법이나 최소 변경안도 비교에서 지우지 않는다.

각 후보를 반대 조건에서 확인한다. 사라졌다고 생각한 비용이 다른 사용자·운영자·단계로 넘어가지는 않는지, 예외·반복 사용·도입 과정에서 새 문제가 생기지는 않는지 검토한다. 상충을 없앨 수 없는 경우에는 남는 선택과 비용을 명확히 한다.

후보 간 근거 수준과 불확실성이 다르면 구별한다. 문헌에 존재하는 해법, 지금 구성한 유추, 실제로 시험한 결과는 같은 증거가 아니다. 현재의 후보가 새로운 특허나 최초 아이디어라고 단정하지 않는다.

## 비교하고 끝낸다

사용자의 목표와 유지 조건에 따라 추천한다. 일부러 후보 수를 늘리거나 자기평가 점수를 붙여 우월성을 만들지 않는다. 필요하면 작은 실험·실물·대표 사례로 불확실성이 큰 가정을 먼저 확인한다.

중요한 해결 수준·작동 방식·제약을 검토했고 새 근거 없이 같은 변형만 나온다면 탐색을 닫는다. 반례가 문제 정의를 바꾸면 그 지점으로 돌아가되, 근거 없이 같은 분석을 반복하지 않는다. 남은 자료·선택·검증이 있으면 무엇이 결론을 바꿀지 제시한다.

결과는 문제를 다시 본 관점, 유력 후보의 차이와 추천 이유, 실제 근거, 남은 불확실성과 최소 검증을 중심으로 쓴다. 검토한 주요 범위와 제외한 범위는 필요할 때 짧게 남긴다. 사용자에게 내부 탐색 기록 전체를 읽게 하지 않는다.
