# 深考モード

十分な時間を使い、現在の問題の言い方の外にある案まで探します。利用者に必要な結果と許可された範囲を守ります。依頼に時間やコストの制限があれば、その中で探索の深さを決めます。

## まず問題の言い方を比べる

与えられた問題、必要な機能、成功を判断する観測、変えられない条件を分けます。利用者が固定した選択と、単に現在使っている手段を混ぜません。事実が足りない場合は問題を閉じず、仮定ごとの候補に分けます。

現在の問題と異なる言い方を比べます。例えば処理速度を上げるか、処理そのものを不要にするか、別の時点で処理するかで、探す解法は変わります。名前だけを抽象化せず、変えた問題の言い方がどの解法を可能にするかを確認します。

## 行き詰まった理由に合う道具を選ぶ

[TRIZの思考道具](triz.md)から必要な部分を読みます。同じ系統の変形を増やす前に、異なる動作の仕組みと解決水準を探します。

| 確認した状況 | 優先して検討する道具 |
|---|---|
| 改善すると別の要求を損なう | 矛盾の根拠確認、条件・時間・空間・全体と部分の分離 |
| 改善するほど構成、説明、工数が増える | 必要な機能と理想的な結果、資源活用、機能の移転・除去 |
| 同じ地点での対処を繰り返す | システム、下位・上位水準、前後の時間、原因と責任の境界 |
| 解法が似た変形にとどまる | 構造的な類推、規模・時間・コストの仮定変更、別の物理・情報作用 |
| 解くべき両立しない条件がまだ定まらない場合の発想 | 利用者の結果、機能、システム境界を変えて機会を探す |

物理・技術システムの難しい発明問題なら、[古典TRIZの深掘り](triz-classical.md)を読み、適した標準解、科学的効果、ARIZの経路まで広げます。全体ARIZを選んだ場合は、最初のアイデアで止まらず、技術化、導入時の問題、繰り返し動作、転用可能性まで検討します。

## 候補を現実の条件へ戻す

有望な候補には、何がどのように動いて問題を解けるかを書きます。他分野の事例を持ち込んだ場合は、対応する機能・両立しない条件と、対応しない条件を分けます。慣れた解法や最小変更案も比較から外しません。

各候補を反対の条件で確かめます。なくなったと思ったコストが別の利用者、運用者、段階へ移っていないか、例外、繰り返し利用、導入の過程で新しい問題が生じないかを検討します。両立しない条件をなくせない場合は、残る選択とコストを明確にします。

候補ごとに根拠の水準と不確実さが異なる場合は分けます。文献にある解法、ここで組み立てた類推、実際に試した結果は同じ証拠ではありません。現在の候補が新しい特許や初めてのアイデアだと断定しません。

## 比べて終える

利用者の目標と維持条件に従って勧めます。候補数を意図的に増やしたり、自己評価の点数で優劣を作ったりしません。必要なら、小さな実験、実物、代表例で、不確実さが大きい仮定を先に確かめます。

重要な解決水準、動作の仕組み、制約を検討し、新しい根拠なしに同じ変形しか出なくなれば探索を閉じます。反例が問題定義を変えるならその地点へ戻りますが、根拠なく同じ分析を繰り返しません。残る資料、選択、検証があれば、何が結論を変えるかを示します。

結果は、問題を捉え直した視点、有力候補の違いと推奨理由、実際の根拠、残る不確実さと最小限の検証を中心に書きます。検討した主な範囲と除外した範囲は、必要なときに短く残します。利用者に内部の探索記録をすべて読ませません。
